### 生命周期
![[Pasted image 20260814140258.png]]
每套生命周期包含一些阶段（phase），阶段是有顺序的，后面的阶段依赖于前面的阶段。

我们看到这三套生命周期，里面有很多很多的阶段，这么多生命周期阶段，其实我们常用的并不多，主要关注以下几个：
- clean：移除上一次构建生成的文件
- compile：编译项目源代码
- test：使用合适的单元测试框架运行测试(junit)
- package：将编译后的文件打包，如：jar、war等
- install：安装项目到本地仓库

Maven的生命周期是抽象的，这意味着生命周期本身不做任何实际工作。**在Maven的设计中，实际任务（如源代码编译）都交由****插件****来完成。

IDEA工具为了方便程序员使用maven生命周期，在右侧的maven工具栏中，已给出快速访问通道。
![[Pasted image 20260814141255.png]]
我们需要关注的就是：`clean` --> `compile` --> `test` --> `package` --> `install`
在同一套生命周期中，我们在执行后面的生命周期时，前面的生命周期都会执行。clean和后面那几个都不在一个生命周期中。

演示 `@ParameterizedTest` ，`@ValueSource` ，`@DisplayName` 注解：

**1. `@DisplayName`——给测试起一个好看的名字**

默认情况下，测试报告里显示的是方法名（比如 `testGetGender2`），加上 `@DisplayName` 可以显示一个自定义的、更易读的说明：

```java
@Test
@DisplayName("测试根据身份证号获取性别")
public void testGetGender2() {
    String gender = new UserService().getGender("612429198904201611");
    Assertions.assertEquals("男", gender);
}
```

运行测试的时候，IDEA 的测试结果面板会显示"测试根据身份证号获取性别"而不是 `testGetGender2`，方便一眼看懂这个测试在测什么，尤其是团队协作、测试报告很多的时候特别有用。

**2. `@ParameterizedTest` + `@ValueSource`——一个方法跑多组数据**

正常的 `@Test` 一次只能测一组固定数据，如果你想用多个不同的身份证号分别测试 `getGender`，普通写法得写好几个 `@Test` 方法，很啰嗦。`@ParameterizedTest` 可以让**同一个方法自动跑多次，每次传入不同的参数**：

```java
@ParameterizedTest
@ValueSource(strings = {
    "612429198904201611", // 男
    "612429198904201612", // 女
    "110002200505091218"  // 男
})
@DisplayName("批量测试性别判断")
public void testGetGenderMulti(String idCard) {
    String gender = new UserService().getGender(idCard);
    System.out.println(idCard + " -> " + gender);
}
```

- `@ValueSource(strings = {...})` —— 提供一组字符串数据，方法会依次拿每一个值当参数跑一遍
- 方法参数 `String idCard` 会自动依次接收 `@ValueSource` 里的每一个值
- 跑完之后，测试报告里会显示这个方法总共跑了 3 次，每次传的什么参数

**`@ValueSource` 除了 `strings`，还支持其他基本类型：**

```java
@ParameterizedTest
@ValueSource(ints = {18, 25, 60})
public void testSomeAgeLogic(int age) {
    // age 会依次是 18, 25, 60
}
```

支持 `strings`、`ints`、`longs`、`doubles`、`booleans` 等，但注意**一次只能传一种类型的数组**，不能像普通方法那样传多个不同参数（如果要测多个参数组合，需要用 `@CsvSource` 之类的更高级注解，这里先不展开）。

---

**小结**

| 注解                   | 作用                                     |
| -------------------- | -------------------------------------- |
| `@Test`              | 标记一个普通测试方法                             |
| `@DisplayName`       | 给测试方法起个好看的展示名字，不影响执行逻辑                 |
| `@ParameterizedTest` | 标记这是一个"参数化测试"，会用多组数据反复跑同一个方法           |
| `@ValueSource`       | 配合 `@ParameterizedTest` 使用，提供一组具体的测试数据 |

实际开发中，`@ParameterizedTest` + `@ValueSource` 最大的价值是**减少重复代码**——同一段验证逻辑，测多组数据（比如边界值、正常值、异常值）时，不用复制粘贴好几个 `@Test` 方法，一个方法配一组数据源就够了。`@DisplayName` 则纯粹是让测试结果更好读，属于锦上添花，不影响功能。

```Java
package com.itheima;

import org.junit.jupiter.api.*;
import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.ValueSource;

@DisplayName("测试-学生业务操作")
public class UserServiceTest {

    @DisplayName("测试-获取年龄")
    @Test
    public void testGetAge(){
        Integer age = new UserService().getAge("110002200505091218");
        System.out.println(age);
    }

    @DisplayName("测试-获取性别")
    @Test
    public void testGetGender(){
        String gender = new UserService().getGender("612429198904201611");
        System.out.println(gender);
    }

    @DisplayName("测试-获取性别3")
    @ParameterizedTest
    @ValueSource(strings = {"612429198904201611","612429198904201631","612429198904201626"})
    public void testGetGender3(String idcard){
        String gender = new UserService().getGender(idcard);
         System.out.println(gender);
    }
}
```

#### 获取请求数据

```java
package com.itheima.controller;

import org.springframework.web.bind.annotation.RequestHeader;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class RequestController {

    /**
     * 请求路径 http://localhost:8080/request?name=Tom&age=18
     */
    @RequestMapping("/request")
    public String request(String name, Integer age, @RequestHeader("User-Agent") String userAgent) {
        System.out.println("name = " + name + ", age = " + age);
        System.out.println("userAgent = " + userAgent);
        return "request success";
    }
}
```

---
**逐行详解**

```java
package com.itheima.controller;
```

声明这个类所在的包路径。表明这个类归属 `com.itheima.controller` 这个包，通常项目里所有Controller类会统一放在 `controller` 这个包下，是一种代码组织约定（跟之前你学的三层架构对应）。

```java
import org.springframework.web.bind.annotation.RequestHeader;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
```

导入这个类要用到的三个 Spring 注解：

- `RequestHeader` —— 用来声明"要获取哪个请求头"
- `RequestMapping` —— 用来声明"这个方法处理哪个路径的请求"
- `RestController` —— 用来标记"这个类是一个返回JSON/文本数据的控制器"

```java
@RestController
```

标记 `RequestController` 这个类是一个"REST风格控制器"，方法的返回值会被Spring自动转成响应体内容直接返回（不是跳转到某个页面），而是直接把返回值本身当作响应内容。

```java
public class RequestController {
```

定义一个公开类，类名叫 `RequestController`——这里类名和"处理请求"这件事对应，是自己起的名字，跟之前讲过的方法命名习惯是同一个道理。

```java
    /**
     * 请求路径 http://localhost:8080/request?name=Tom&age=18
     */
```

这是Java的**文档注释**（以 `/**` 开头），说明下面这个方法对应的完整访问路径长什么样，方便阅读代码的人一眼看懂怎么触发这个接口，属于良好的代码规范习惯。

```java
    @RequestMapping("/request")
```

声明这个方法负责处理路径为 `/request` 的请求。`@RequestMapping` 默认不限定请求方式，GET、POST 都能匹配上这个方法（之前详细讲过这个注解的用法）。

```java
    public String request(String name, Integer age, @RequestHeader("User-Agent") String userAgent) {
```

方法签名，拆开看每个部分：

- `public` —— 访问修饰符，Spring要求处理请求的方法必须是public，否则框架调不到
- `String` —— 返回值类型，表示这个方法执行完要返回一段文字内容
- `request` —— 方法名，自己起的（跟接口路径 `/request` 恰好同名，方便对应，但没有强制要求）
- `String name` —— 方法参数，Spring会自动去请求里找一个叫 `name` 的参数，把值取出来赋给这个变量
- `Integer age` —— 同理，自动去找 `age` 参数，**并且自动把字符串转成 `Integer` 类型**（原生写法里 `getParameter` 只能拿到 `String`，还要自己手动转，这里Spring帮你省了这一步）
- `@RequestHeader("User-Agent") String userAgent` —— 声明"我要获取请求头里叫 `User-Agent` 的那个值"，Spring自动帮你取出来，赋给 `userAgent` 这个变量

**这一行本身没有任何手动获取参数的代码**——所有值（`name`、`age`、`userAgent`）都是Spring在调用这个方法**之前**就已经自动准备好、注入进方法参数里了，你写方法体的时候可以直接拿来用。

```java
        System.out.println("name = " + name + ", age = " + age);
```

打印刚才自动获取到的参数值到控制台，用字符串拼接把 `name` 和 `age` 的值嵌进去，输出类似 `name = Tom, age = 18`。

```java
        System.out.println("userAgent = " + userAgent);
```

打印自动获取到的 `User-Agent` 请求头值，输出类似浏览器的标识字符串（比如 `Mozilla/5.0 ...`）。

```java
        return "request success";
```

方法返回一个字符串 `"request success"`。因为类上标了 `@RestController`，这个返回值会被Spring直接当作响应体内容，原样发回给发请求的一方（浏览器/axios），前端收到的响应体就是这段纯文本。


#### 设置响应数据
```Java
package com.itheima.controller;

import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class ResponseController {

    @RequestMapping("/response")
    public ResponseEntity<String> response() {
        return ResponseEntity
                .status(401)
                .header("name", "itcast")
                .body("<h1>hello response</h1>");
    }
}
```

---
**逐行详解**

```java
package com.itheima.controller;
```

声明包路径。这里我把包名从原来的 `com.itheima` 改成了 `com.itheima.controller`——跟上一个 `RequestController` 保持一致，两个Controller类都归到同一个 `controller` 包下，符合三层架构的项目组织规范。

```java
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
```

导入用到的三个东西：

- `ResponseEntity` —— 用来封装"完整的HTTP响应"（状态码+响应头+响应体）
- `RequestMapping` —— 声明这个方法处理哪个路径的请求
- `RestController` —— 标记这是一个返回数据的控制器

**注意**：原来代码里的 `import jakarta.servlet.http.HttpServletResponse;` 和 `import java.io.IOException;` 都删掉了——因为不再手动操作 `HttpServletResponse`，也就不会抛 `IOException`（原来的 `getWriter()` 方法会抛这个异常，所以方法上要加 `throws IOException`；现在没用这个方法了，自然也不需要这个异常声明了）。

```java
@RestController
```

标记这个类是REST风格控制器，方法返回值会被Spring自动处理成响应内容返回给前端。

```java
public class ResponseController {
```

定义类，类名 `ResponseController`，跟它负责"处理响应"的职责对应。

```java
    @RequestMapping("/response")
```

声明这个方法处理路径为 `/response` 的请求。

```java
    public ResponseEntity<String> response() {
```

方法签名：

- `public` —— 访问修饰符，必须是public才能被Spring框架正常调用
- `ResponseEntity<String>` —— 返回值类型，表示"这个方法要返回一个完整的HTTP响应，响应体的数据类型是String"
- `response()` —— 方法名（跟接口路径同名，方便对应），**括号里没有任何参数**——因为不再需要 `HttpServletResponse response` 这个参数了，构建响应完全靠 `ResponseEntity` 自身的链式方法完成，不需要借助Tomcat自动传入的原生响应对象

```java
        return ResponseEntity
```

开始构建并返回一个 `ResponseEntity` 对象，用**链式调用**（builder模式）依次设置各项内容。

```java
                .status(401)
```

设置这次响应的HTTP状态码为401（Unauthorized，未授权）。

```java
                .header("name", "itcast")
```

设置一个自定义响应头，键是 `"name"`，值是 `"itcast"`。


#### @ResponseBody

前面我们学习过HTTL协议的交互方式：请求响应模式（有请求就有响应）。那么Controller程序呢，除了接收请求外，还可以进行响应。
在我们前面所编写的controller方法中，都已经设置了响应数据。
controller方法中的return的结果，怎么就可以响应给浏览器呢？
答案：使用@ResponseBody注解


**@***ResponseBody****注解：

- 类型：方法注解、类注解
    
- 位置：书写在Controller方法上或类上
    
- 作用：将方法返回值直接响应给浏览器，如果返回值类型是实体对象/集合，将会转换为JSON格式后在响应给浏览器

但是在我们所书写的Controller中，只在类上添加了@RestController注解、方法添加了@RequestMapping注解，并没有使用@ResponseBody注解，怎么给浏览器响应呢？

这是因为，我们在类上加了@RestController注解，而这个注解是由两个注解组合起来的，分别是：@Controller 、@ResponseBody。 那也就意味着，我们在类上已经添加了@ResponseBody注解了，而一旦在类上加了@ResponseBody注解，就相当于该类所有的方法中都已经添加了@ResponseBody注解。

> 提示：前后端分离的项目中，一般直接在请求处理类上加@RestController注解，就无需在方法上加@ResponseBody注解了。
