#### 静态变量和静态方法
对象共享的内容。我们通过使用`static`关键字来声明一个变量或一个方法为静态的，一旦被声明为静态，那么通过这个类创建的所有对象，操作的都是同一个目标
```java
public class Person {
    String name;
    int age;
    String sex;
    static String info;    //这里我们定义一个info静态变量
}
```
```java
public static void main(String[] args) {
    Person p1 = new Person();
    Person p2 = new Person();
    p1.info = "杰哥你干嘛";  //类名.info=赋值，跟对象无关
    System.out.println(p2.info); 
    System.out.println(Person.info);   //可以看到，由于静态属性是属于类的，因此无论通过什么方式改变，都改变的是同一个目标
}
```

静态方法只能访问静态对象。
**静态成员是"类级别"的,只有一份;实例成员是"对象级别"的,每个对象各有一份。** 静态方法不跟任何一个对象绑定,所以它天生够不着那些"每个对象各有一份"的东西。
**非静态方法(实例方法)可以自由访问静态变量**
```java
public class Student {
    static int schoolCount = 10;   // 静态变量,属于类
    int age;                        // 实例变量,属于对象

    static void printInfo() {
        System.out.println(schoolCount);  // ✅ 正确,静态方法访问静态变量
        System.out.println(age);          // ❌ 编译错误! Cannot make a static reference...
    }

    void printAge() {
        System.out.println(age);  // ✅ 正确,非静态方法可以访问实例变量
        System.out.println(schoolCount); // ✅ 正确,可以访问静态变量
    }
}

```

## 封装、继承和多态

### 类的封装
```java
public class Person {
    private String name;    //现在类的属性只能被自己直接访问
    private int age;
    private String sex;
  
  	public Person(String name, int age, String sex) {   //构造方法也要声明为公共，否则对象都构造不了
        this.name = name;
        this.age = age;
        this.sex = sex;
    }

    public String getName() {
        return name;    //想要知道这个对象的名字，必须通过getName()方法来获取，并且得到的只是名字值，外部无法修改
    }

    public String getSex() {
        return sex;
    }

    public int getAge() {
        return age;
    }
}
```

```java
public static void main(String[] args) {
    Person person = new Person("小明", 18, "男");
    System.out.println(person.getName());    //只能通过调用getName()方法来获取名字
}
```

### 类的继承
```java
public class Worker extends Person{    //工人类，Person被继承

}
```

类的继承可以不断向下，但是同时只能继承一个类，同时，标记为`final`的类不允许被继承：
```java
public final class Person {  //class前面添加final关键字表示这个类已经是最终形态，不能继承
}
```

子类权限 = 你自己给子类写的修饰符，跟父类是否 `public` 无关；
父类不加 `public` 只影响：**父类这个类型名**能不能在包外被直接引用/继承；
子类若是 `public`，那么它从父类继承来的 `public` 成员，外部包依然可以通过子类正常访问到。

我们在使用子类时，可以将其当做父类来使用：
```java
public static void main(String[] args) {
    Person person = new Student("小明", 18, "男");    //这里使用父类类型的变量，去引用一个子类对象（向上转型）
    person.hello();    //父类对象的引用相当于当做父类来使用，只能访问父类对象的内容
}
```
左边`Person`是声明的**变量类型(编译时类型)**,右边`new Student(...)`创建的是一个**真实的对象类型(运行时类型)**。用父类类型的变量去指向一个子类对象,这个动作就叫**向上转型**——因为类的继承关系图里,父类通常画在上面,子类画在下面,"子类变成父类"看起来就是"往上走"。
###### 为什么可以这么写?
`Student`继承自`Person`,那么"每一个Student必然也是一个Person"**(学生是人的一种)。既然一个`Student`对象本身就具备`Person`的全部特征(所有`Person`有的属性、方法,`Student`都有,因为继承下来了),那用`Person`这个"更宽泛"的类型去装它,自然是安全、合法的——这就跟你说"这是一只狗"和"这是一个动物"都对一样,狗天生就属于动物的范畴。

##### 编译时类型和运行时类型有什么区别？
```java
Person person = new Student("小明", 18, "男");
```
这一行代码里,其实藏着**两个不同的"类型"**:
- **编译时类型(Compile-time Type)**:等号**左边**声明的类型,也就是变量`person`本身被声明成的类型——`Person`。这个类型在代码写完、编译完成之后就**永远固定不变**,只有编译器在检查语法、决定"这个变量能调用哪些方法"时才会用到它。
- **运行时类型(Runtime Type)**:等号**右边**`new`出来的、这个对象**真正的、实际的类型**——`Student`。这个类型只有程序**真正跑起来**、创建对象的那一刻才能确定,它反映的是"这个对象本质上到底是什么"。
编译器在检查这行代码、以及后面所有用到`person`的代码时,**只认左边的`Person`**,完全不关心右边实际`new`的是什么。而程序真正运行起来后,内存里实实在在存在的那个对象,**骨子里是`Student`**,它拥有`Student`的全部东西(包括`Student`独有的属性、方法,以及它重写过的方法)。


```java
Person person = new Student("小明", 18, "男");
person.hello();   // ✅ 能调用,前提是Person类里有hello这个方法(不管Student有没有重写它)
person.study();   // ❌ 编译直接报错!因为Person类里根本没有study方法,哪怕Student类明明有study方法,编译器也不认
```

编译器做这个检查时,**完全不会去看`new`的是什么**,它只根据变量声明的类型(`Person`)去查这个类里"有没有这个方法"。这也是为什么向上转型之后"只能访问父类的内容"——不是父类对象本身缺胳膊少腿,而是编译器压根不让你调用父类里没有的方法。

打个比方:你把一个"学生证"硬塞进一个只写着"身份证"字样的信封里,信封上写的是"身份证",别人拿到这个信封时,只会按"身份证能干的事"来对待它(比如只能验证你的公民身份),不会知道里面其实还能刷学生食堂——**变量的类型决定了"能看到什么、能调用什么",而不是对象实际是什么**。


```java
class Person {
    void hello() {
        System.out.println("我是Person的hello");
    }
}

class Student extends Person {
    @Override
    void hello() {
        System.out.println("我是Student重写后的hello");
    }
}

Person person = new Student("小明", 18, "男");
person.hello();   // 输出: 我是Student重写后的hello
```
虽然编译器只根据`Person`类型允许你调用`hello()`,但**真正执行的时候**,JVM会去看这个对象**实际的运行时类型**是`Student`,如果`Student`重写(override)了`hello`方法,那就执行`Student`版本的`hello`,而不是`Person`原本的版本。这就是**多态的核心机制:方法能不能调、看编译时类型;调用哪个版本的方法体、看运行时类型**,专业说法叫"**动态绑定**"或"**运行时多态**"。

**编译时类型决定"你能敲哪扇门"(能调用哪些方法名),运行时类型决定"敲开门之后到底是谁来开门、说了什么话"(具体执行哪个方法体)。** 这一整套机制,正是Java多态得以实现的底层原理——同一句`person.hello()`,写在代码里的样子永远不变,但根据`new`的对象不同,实际表现出的行为可以完全不同。

#### 如果子类加点别的变量还能这样用吗（向上转型）？
可以,完全没问题——向上转型这个动作本身**永远合法**,不管子类加了多少新变量、新方法都不影响。但正因为编译器"只认编译时类型",子类新增的那些变量,**通过父类类型的变量是访问不到的**。
```java
class Person {
    String name;
    int age;

    Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    void hello() {
        System.out.println("我叫" + name);
    }
}

class Student extends Person {
    String school;   // ⭐ Student新增的变量,Person里没有

    Student(String name, int age, String school) {
        super(name, age);   // ⭐ 调用父类的Person(String, int)构造方法,把name和age交给父类去初始化
        this.school = school;
    }

    void study() {    // ⭐ Student新增的方法,Person里没有
        System.out.println(name + "在" + school + "学习");
    }
}
```

```java
public static void main(String[] args) {
    Person person = new Student("小明", 18, "清华大学");

    person.hello();          // ✅ 可以,Person类里有hello方法
    person.name;              // ✅ 可以,Person类里有name变量

    person.school;            // ❌ 编译报错! Person类里根本没有school这个变量
    person.study();           // ❌ 编译报错! Person类里根本没有study这个方法
}
```
报错信息大概长这样:
```
error: cannot find symbol
        person.study();
              ^
  symbol:   method study()
  location: variable person of type Person
```
#### 为什么会这样?——跟上一个问题的原理完全一致
`person`这个变量的**编译时类型**始终是`Person`,编译器检查代码时,只会去`Person.class`这个类定义里找有没有`study`、有没有`school`这些名字——它压根不知道、也不关心你右边`new`的其实是功能更丰富的`Student`。哪怕这个对象在内存里**确确实实**拥有`school`这个字段、`study`这个方法(因为运行时类型是`Student`),但只要编译器这一关过不去,程序就跑不起来。

这时候就要用到"向下转型"(Downcasting),把父类类型的引用**强制转回**子类类型,才能重新访问子类独有的东西:
```java
Person person = new Student("小明", 18, "清华大学");

Student student = (Student) person;   // 向下转型,强制转换
student.study();                       // ✅ 现在可以了,因为student的编译时类型是Student
```
不过向下转型要小心,如果这个对象实际的运行时类型根本不是`Student`(或者它的子类),转换会在运行时直接抛出`ClassCastException`异常,这个之后遇到具体场景时可以再细说。

**子类新增的变量、方法是真实存在于对象里的,只是"父类类型的门牌号"上找不到它们的名字,所以编译器不让你直接敲这扇门去要。** 这也是"编译时类型决定能调用什么"这条规则最直观的体现——你多学的本事,老同学(父类)的通讯录里是查不到的。

![[Pasted image 20260714222344.png]]
**向上转型的意义不在于"限制访问"本身,而在于"用一个更通用的类型,统一处理各种不同的子类对象",这是实现多态、写出灵活可扩展代码的基础。** 


#### 向下转型：
```java
public static void main(String[] args) {
    Person person = new Student("小明", 18, "男");
    Student student = (Student) person;   //使用强制类型转换（向下转型）
    student.study();
}
```
`(Student)`这种"类型名放在括号里"的写法叫**强制类型转换(cast)**,意思是告诉编译器:**"我确定`person`这个变量背后指向的对象实际上是一个`Student`,请把它当成`Student`类型来对待。"**


子类是可以定义和父类同名的属性的：此时父类的name属性和子类的name属性是同时存在的。
```java
// 文件: Person.java
public class Person {
    protected String name;
    protected int age;
    protected String sex;

    public Person(String name, int age, String sex) {
        this.name = name;
        this.age = age;
        this.sex = sex;
    }

    public void hello() {
        System.out.println("我是Person的hello,name=" + name);
    }
}
```

```java
// 文件: Worker.java
public class Worker extends Person {
    protected String name;   // ⭐ 子类同样定义了一个name,和父类的name同名
    protected String job;

    public Worker(String name, int age, String sex, String job) {
        super(name, age, sex);   // 传给父类的构造方法,初始化"父类那一份"name
        this.name = name;         // 再单独赋值给"子类自己那一份"name
        this.job = job;
    }

    public void printBoth() {
        System.out.println("子类自己的name: " + this.name);
        System.out.println("父类的name: " + super.name);   // ⭐ 用super专门去拿父类那一份
    }
}
```

```java
// 文件: Main.java
public class Main {
    public static void main(String[] args) {
        Worker worker = new Worker("小明", 25, "男", "程序员");
        worker.printBoth();
    }
}
```

**子类定义同名字段,不是"覆盖",而是"新增了一份、并把父类那份挡住了"——两份数据同时存在于内存里,想访问哪一份,取决于你是用什么类型的"眼睛"(编译时类型)去看这个对象,或者干脆用`super.字段名`直接点名要父类那一份。** 这也是为什么实际开发中通常**不建议**子类定义和父类同名的字段——很容易搞混,增加维护成本,如果只是想改变父类字段的值,直接在子类构造方法里用`super(...)`或者`this.父类字段 = xxx`赋值就够了,没必要另起一份。


### (Java 16) 类型判断模式匹配
在Java 14，`instanceof`迎来了一波小更新，之前我们判断某个对象是否为某个类型或是某个类型的子类时，会用到`instanceof`关键字：
```java
public static void main(String[] args) {
    test(new Student());
}

//实现如果是学生就执行study方法
private static void test(Person person) {
    if(person instanceof Student) {   //首先判断是否为学生类型
        Student student = (Student) person;  //如果是直接进行强制类型转换
        student.study();   //执行学习
    }
}

static class Person { }
static class Student extends Person {
    void study() {
        System.out.println("我要打瓦");
    }
}
```
但是这个版本`instanceof`加强之后，我们就不需要了，我们可以直接将student替换为模式变量：
```java
private static void test(Person person) {
    if(person instanceof Student student) {  //直接在instanceof后写变量名称，作为判断成功之后转换的此类型变量名称
        student.study();
    }
}
```
